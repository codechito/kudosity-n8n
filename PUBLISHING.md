# Publishing & Deployment Guide

How to build, test, and make `n8n-nodes-kudosity` available to clients on their n8n instances.

---

## Prerequisites

- Node.js 18+ and npm installed
- n8n installed locally (for testing)
- An npm account (for publishing to the npm registry)

---

## 1. Install dependencies and build

```bash
cd kudosity-n8n
npm install
npm run build
```

This compiles all TypeScript in `nodes/` and `credentials/` to `dist/`. The `dist/` folder is what n8n actually loads.

> If the build fails on `gulp build:icons`, install gulp globally:
> ```bash
> npm install -g gulp-cli
> ```
> Or simplify the build script in `package.json` to just `tsc` while developing — the SVG icon is already in the right place.

---

## 2. Test locally before publishing

### Option A — Link into a local n8n install

```bash
# In the kudosity-n8n directory
npm run build
npm link

# In your n8n config directory (usually ~/.n8n)
cd ~/.n8n
npm link n8n-nodes-kudosity
```

Then start n8n:

```bash
n8n start
```

Open `http://localhost:5678` — search for "Kudosity" in the node panel. Both **Kudosity** and **Kudosity Trigger** should appear.

### Option B — Set the N8N_CUSTOM_EXTENSIONS env variable

```bash
N8N_CUSTOM_EXTENSIONS="/home/chito/kudosity-n8n/dist" n8n start
```

---

## 3. Verify the node works

1. Create a new credential using a real Kudosity API key — the credential test hits `GET /sms?limit=1` and should return a green tick
2. Add a **Kudosity** node, select **Send SMS**, fill in a real number and sender, and execute — confirm you receive the SMS
3. Add a **Kudosity Trigger** node, activate the workflow, and check the Kudosity portal under **Settings → Webhooks** that the webhook was registered
4. Deactivate the workflow and confirm the webhook is removed from the Kudosity portal

---

## 4. Publish to npm

This is the easiest way for clients to install the node on any n8n instance.

### 4a. Bump the version

```bash
npm version patch   # 0.1.0 → 0.1.1  (bug fix)
npm version minor   # 0.1.0 → 0.2.0  (new feature)
npm version major   # 0.1.0 → 1.0.0  (breaking change)
```

### 4b. Publish

```bash
npm login           # only needed once
npm publish --access public
```

The package will be live at `https://www.npmjs.com/package/n8n-nodes-kudosity`.

> **Important:** The `package.json` `"files"` field is set to `["dist"]` — only the compiled output is published, not source TypeScript.

---

## 5. Client installation — n8n Cloud

Clients on **n8n Cloud** can install community nodes from the UI:

1. Go to **Settings → Community Nodes**
2. Click **Install**
3. Enter the package name: `n8n-nodes-kudosity`
4. Click **Install** and confirm

The Kudosity nodes will appear in the node panel immediately.

---

## 6. Client installation — Self-hosted n8n

### Option A — Via the UI (n8n v0.187+)

Same as cloud — go to **Settings → Community Nodes → Install** and enter `n8n-nodes-kudosity`.

### Option B — Via npm (manual)

```bash
# Find the n8n user data directory (default: ~/.n8n)
cd ~/.n8n

# Install the package
npm install n8n-nodes-kudosity

# Restart n8n
```

### Option C — Docker

If the client runs n8n in Docker, they need to install the node into the container. The recommended way is a custom Dockerfile:

```dockerfile
FROM n8nio/n8n

USER root
RUN cd /usr/local/lib/node_modules/n8n && \
    npm install n8n-nodes-kudosity

USER node
```

Build and run:

```bash
docker build -t n8n-with-kudosity .
docker run -it --rm \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  n8n-with-kudosity
```

Alternatively, use the `N8N_CUSTOM_EXTENSIONS` environment variable to point to a mounted directory containing the built package:

```yaml
# docker-compose.yml
environment:
  - N8N_CUSTOM_EXTENSIONS=/home/node/.n8n/custom
volumes:
  - ./kudosity-n8n/dist:/home/node/.n8n/custom/n8n-nodes-kudosity/dist
```

---

## 7. Updating the node

1. Make your code changes
2. Run `npm run build`
3. Bump the version with `npm version patch|minor|major`
4. Run `npm publish --access public`
5. Clients on n8n Cloud — they will see an update available in **Settings → Community Nodes**
6. Clients on self-hosted — they run `npm update n8n-nodes-kudosity` in their `.n8n` directory and restart n8n

## Troubleshooting

**Node doesn't appear in n8n after install**
- Confirm n8n was restarted after installation
- Check that `dist/` exists — run `npm run build` if not
- Check the n8n logs for errors loading the node

**Credential test fails**
- Confirm the API Key is correct (no extra spaces)
- Confirm the Kudosity account has API access enabled

**Webhook not registering**
- Confirm the workflow is **Activated** (not just saved)
- Confirm the n8n instance is publicly reachable — Kudosity needs to be able to POST to the webhook URL
- For local testing, use a tunnel tool like `ngrok` or `cloudflared` and set `N8N_WEBHOOK_URL` to the tunnel URL:
  ```bash
  N8N_WEBHOOK_URL=https://your-tunnel.ngrok.io n8n start
  ```

**Webhook not deleting on deactivation**
- Check the Kudosity portal under **Settings → Webhooks** and delete manually if needed
- This can happen if the webhook ID stored in n8n's static data goes out of sync
